LegalFlow / Legatia

A legal operations product designed to bring clients, cases, documents, tasks, hearings and deadlines into one workspace.

The problem

Legal information often fragments across documents, chats, calendars and spreadsheets. The product centralizes operational context for each client and case.

Constraints

  • Access follows firm, user and role boundaries.
  • The product had to support an evolving MVP and beta flow.
  • Frontend state had to remain aligned with remote API data.

My responsibility

I worked across the React frontend and Node.js/TypeScript backend, contributing to product flows, API integration, validation and role-aware behaviour.

Architecture

React + Vite + Tailwind CSS → remote-state queries and routing → Express + Sequelize → MySQL, with Docker Compose, Nginx and Linux documented as the infrastructure context.

React / ViteRemote stateExpressMySQL

Key engineering decisions

Role-aware data access

Permissions belong to the product model, not only to visual hiding in the client.

Remote-state queries

Client, case and onboarding interfaces stay predictable while server data changes.

Structured validation

Zod clarifies the contracts where user input and API payloads meet.

What I built

  • Client and case management flows.
  • Onboarding and beta requests.
  • Firm, user and role-aware product surfaces.
  • Documents, tasks, hearings and deadlines as product modules.

Hard problems

Filtering client data by creator and access rules, designing a multi-user firm model and keeping onboarding useful while the product evolved.

Quality & testing

Validation and frontend/API integration are part of the implementation story. Detailed test evidence will be added only when the evidence pack is available.

Deployment & operations

Docker Compose, Nginx and Linux are the documented infrastructure context. No production metric is claimed.

Results

The system creates one operational surface for legal firms. Quantitative impact is intentionally not claimed until the product status and usage are confirmed.

What I would improve today

  • Add user-visible audit trails for sensitive case changes.
  • Expand automated access-control tests.
  • Document the MVP-to-beta learning loop.
